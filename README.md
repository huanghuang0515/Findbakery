# Gothel's Garden — 品牌形象首頁

依據設計稿 `首頁 (1).png`（1920 × 5420）復刻的靜態網站，純 HTML + CSS + JavaScript，**無任何建置流程與外部相依**，直接用瀏覽器開啟 `index.html` 即可。

## 與設計稿的對應

版面以設計稿的 1920px 畫布為基準，關鍵數值均以像素掃描量測後換算成百分比／`clamp()`，因此在任何寬度下都維持相同比例。

> **注意**：初期版本是照設計稿做像素級對位，後來依需求改以**視覺和諧優先**，
> 重建了一套統一的水平基準、字級級距與垂直節奏。
> 因此版位已**不再與設計稿 1:1 對應**，主體構圖與素材則維持一致。

### 水平基準（只有一組）

全站左右一律對齊版心 **1680px**（1920 時為 x 120–1800），且左右對稱：

| 元素 | 對齊方式 |
|---|---|
| 版心 | `.shell` `max-width: 1680px + 左右留白` |
| 導覽列上下框線 | 貼齊版心邊緣（先前是另一組 64px 內縮） |
| 首屏左右裝飾直線 | 分別貼齊版心左、右邊緣（先前右線距右緣 159px，左右不對稱） |
| 小麥圖、首屏導言 | 右緣貼齊版心 |
| 大標題、首屏內文 | 自版心邊緣內縮 `--indent`（96px / 5.714%） |

首屏元素改以 `.hero__inner` 為基準容器（寬度＝版心）。
先前各元素用「視窗寬的百分比」定位，版心佔比會隨視窗寬度變動而逐漸錯開；
改以版心為基準後，任何寬度下都對齊同一組邊界。

### 字級級距

先前存在 `.73 / .78 / .83 / .833vw` 這類彼此只差一點點的零散值，已整併為級距變數
（`--fs-xs` ~ `--fs-hero`），並統一中文內文行高為 `1.95`
（先前首屏 1.69、品牌故事 2.4，落差過大）。

### 垂直節奏

區塊間距統一為 `--sp-block`、標題到內容為 `--sp-head`，
先前的 187/96/140/90 各自為政已移除。實測相鄰區塊間距為 89/89/88，
標題到卡片 131/131，分隔線到標題 116/116。

### 頁首高度

|---|---|---|
| logo 區 | 244px | 180px |
| 導覽列 | 97px | 80px |
| 合計 | 341px | **260px** |

## 購買流程

首頁 → 商品詳情 → 購物車 → 結帳 → 完成，四頁為獨立 HTML，共用同一份
localStorage 購物車（無後端，資料僅存本機、不跨裝置同步）。

### 資料層 `assets/js/store.js`（`window.GG`）
單一真實來源，四頁與首頁皆引用：

| 功能 | API |
|---|---|
| 商品目錄 | `GG.catalog()`、`GG.find(id)` |
| 購物車 | `GG.addItem(id,qty)`、`GG.setQty(id,qty)`、`GG.removeItem(id)`、`GG.clearCart()` |
| 讀取 | `GG.getCart()`、`GG.lines()`（展開含商品明細） |
| 金額 | `GG.count()`、`GG.subtotal()`、`GG.shipping()`、`GG.total()`、`GG.money(n)` |
| 訂單 | `GG.saveOrder(o)`、`GG.getOrder()` |
| 頁首件數 | `GG.mountBadge()`（監聽變更 + 跨分頁 `storage` 同步） |

- **運費**：小計 ≥ $800 免運，否則 $120（購物車／結帳／完成三處金額一致）。
- 購物車變更以 `gg:cartchange` 事件廣播，頁首件數即時更新；空車時徽章隱藏。

### 各頁重點
- **商品詳情**：依 `?id=` 顯示；數量增減（1–99）、加入購物車、下方「其他商品」。
- **購物車**：列表可改數量／移除即時重算；空車顯示引導狀態；訂單摘要含免運提示。
- **結帳**：收件人／配送／付款；前端驗證（姓名、電話、Email、地址），
  門市自取時地址欄隱藏且免必填；送出即產生訂單編號並寫入 `gg.lastOrder`。
- **完成**：顯示訂單編號、明細、金額與收件資訊，載入時清空購物車；
  直接進入（無訂單資料）會導回首頁。

### 已驗證（headless 渲染 + 真實瀏覽器 DOM 量測）
加入購物車持久化、數量與移除的金額重算、免運門檻、結帳驗證擋下空表單、
下單產生訂單並清空購物車、桌機／390 手機版版面、空車狀態、四頁皆無 console error。

> **限制**：純前端、無金流與後端，付款方式與「刷卡」僅為畫面示意；
> 購物車與訂單存於瀏覽器 localStorage，不跨裝置、清除瀏覽器資料即消失。

## 首頁動態效果

動畫參數集中在 `style.css` 的 `:root`（`--dur-*`、`--stagger-*`、`--ease-soft`），
各區塊一律引用，避免速度不一致。整條流程為：
**首次進入 → 星花描線＋倒數 → Loading 淡出 → 首屏分層進場 → 滾動揭露**。

### 品牌 Loading 開場
- 八瓣幾何星花線稿以 `stroke-dasharray`／`stroke-dashoffset`（`pathLength="1"`）逐瓣描繪，
  外圈圓弧由頂端順時針畫一圈、末端帶小圓點，約 3 秒完成；底稿為極淡完整星花。
- 襯線倒數 `03 → 02 → 01`（每秒一次、向上位移淡入）＋標語，最後停留約 150ms 再淡出。
- **播放規則：每次載入都播放**（不記錄是否看過）。倒數為品牌效果，**不代表真實載入進度**。
- 「略過開場」可鍵盤操作；開場期間背景設 `inert`，結束後焦點移回 `#main`。
- **逃生口**：`?nointro` 直接跳過；`?replay` 可覆寫 `prefers-reduced-motion`
  （自動播放仍完全尊重減少動態設定，`force-intro` 於開場結束即移除）。

> **看不到開場動畫時**，依序確認：
> 1. 作業系統是否開了「關閉動畫」（Windows 設定 →「協助工具」→「視覺效果」→「動畫效果」）
>    → 此時會依規格跳過開場；要強制觀看請用 `?replay`。
> 2. 網址是否帶了 `?nointro`。
> 3. 本專案為純靜態檔，**直接雙擊 `index.html` 開啟即可**，不需要啟動任何伺服器。

> ⚠️ **命名注意**：`<html>` 的開場狀態 class 是 **`is-intro`**，不可改回 `intro`。
> 遮罩 `<div>` 本身的 class 就叫 `intro`，若兩者同名，`.intro{display:none}`
> 會一併命中 `<html>`，導致**整頁空白**（此坑已踩過）。

### 首屏分層進場
Logo→導覽（+100ms）→拱形照（`scale` 回正＋淡入 ~1.05s）→標題兩行（`translateY` 16px，
第二行 +120ms）→麥田照→簡介／花紋／星花，交錯約 1.5 秒完成，期間仍可捲動點擊。

### 滾動揭露（`IntersectionObserver`，約 12% 進入觸發，只播一次）
- 一般揭露：`opacity 0→1` + `translateY`。
- **商品卡依「同排欄位」stagger 80ms**（`idx % 欄數`），不累加整頁索引；欄數隨斷點重算。
- 分隔線由中央 `scaleX(0→1)` 向左右展開，中央星花隨後淡入。
- 圖文（品牌故事）圖先、文字 `data-reveal-delay="120"`。

### 視差與滑鼠互動（僅桌面 ≥1025px）
- 拱形／麥田照以 CSS `mask` 把**外框**與**內部影像**分離：外框（遮罩）固定，
  內部 `<img>` 常駐 `scale(1.12)` 預留裁切餘裕，位移層再依捲動＋滑鼠微移（總量 <12px），**不露白**。
- 進場 `scale` 放在 `<img>`、視差 `translate` 放在 `.hero__media`，**分層避免 transform 互相覆寫**。
- rAF **隨需喚醒**：值收斂即停，不做持續空轉的迴圈。手機停用視差。

### 收藏功能的限制
收藏沿用既有邏輯，狀態存 `localStorage`（`gg.favourites`），切換成功才填色並 pop。
**目前無後端 API 與登入**，因此收藏僅存在本機瀏覽器、不跨裝置同步——這是既有架構的限制，
未另建假的持久化。

### 清理與韌性
`main.js` 內有清理登錄，`pagehide` 時解除 observer / timer / rAF / 事件監聽。
開場的隱藏初始態只在 `html.intro` 下生效，且 `<head>` 有 4.5s 安全逾時＋`try/catch`：
**JS 或動畫初始化失敗時，主要內容仍會顯示，Loading 不會永久遮住網站。**

## 頁首為什麼用 `fixed` 而不是 `sticky`

頁首吸頂時會從 244px 縮到 100px（1920 時落差 144px，1440 時 108px）。
若頁首留在文件流中（`position: sticky`），這個高度變化會連帶推動整份文件：

1. 捲過 40px → 加上 `is-stuck` → 頁首縮小，下方內容整體上移 100 多 px
2. 瀏覽器的捲動錨定（scroll anchoring）為了讓畫面內容不跳動，反向修正 `scrollY`
3. 修正後的 `scrollY` 又掉回 40px 以下 → 移除 `is-stuck` → 頁首變高 → 回到步驟 1

**位移量（108–144px）遠大於觸發門檻（40px）**，所以在頁面頂端附近永遠無法收斂，
表現出來就是持續抖動。

解法有兩層：

- `position: fixed` + `.header-spacer` 佔位 → 頁首高度變化完全不影響文件流，迴圈被切斷
  （實測把頁首從 60px 撐到 400px，內容位移與文件高變化皆為 0）
- JS 改用兩段式門檻（向下 120px 才縮、向上 40px 才展開），避免臨界點被細微捲動反覆觸發

連帶要處理的兩件事：

- 錨點連結需要 `scroll-margin-top`，否則目標標題會被固定頁首蓋住
- ≤1024px 時導覽列收進漢堡選單，佔位高度要同步改為只算頁首上半部

## 行動選單為什麼不用 `grid-template-rows: 0fr → 1fr`

那是常見的展開動畫寫法，但在這個結構下**軌道只會解析到 `ul` 的 padding 高度（26px）**，
八個選單項目全被 `ul` 的 `overflow: hidden` 裁掉——版面位置正常、視覺上卻只剩一條，
實測八個項目的 `elementFromPoint` 全部落在後方的首屏區塊，等於整個行動選單不可點擊。

改用 `max-height` 展開即可。要注意 **捲動容器不能設在 `.main-nav` 或其 `ul`**：
兩者一旦成為捲動容器，自動最小高度會歸零，選單同樣會塌掉。

## 開發備註

### 重新產生圖片

修改裁切位置後執行（需 Windows PowerShell）：

```powershell
powershell -ExecutionPolicy Bypass -File assets\img\build-images.ps1
```

腳本會從 `assets/img/source/` 讀取原始照片，依 `-FocusX` / `-FocusY`
（0 = 靠左／上，1 = 靠右／下）決定裁切重心，輸出品質 82 的 JPEG。

> 注意：此腳本含中文註解，若要編輯請以 **UTF-8 with BOM** 儲存，
> 否則 Windows PowerShell 5.1 會以 ANSI 讀取而解析失敗。

### 更換商品

商品內容集中在 `assets/js/main.js` 最上方的 `SUBSCRIPTIONS` 與 `PRODUCTS`
兩個陣列，欄位為 `id` / `name` / `price` / `sold` / `img` / `alt`。

### 本機預覽

直接雙擊 `index.html` 即可。若需要以 HTTP 提供（測試 `localStorage`、快取等）：

```powershell
node .claude\static-server.js
```
